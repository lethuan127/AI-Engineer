- [Breaking the Lockstep Turn — Async Tool Calls, Mid-Turn Steering, and Configuration Updates](Breaking%20the%20Lockstep%20Turn%20—%20Async%20Tool%20Calls,%20Mid-Turn%20Steering,%20and%20Configuration%20Updates.md) — the companion to the note above, one level down: Background Agents made the work *around* the loop asynchronous, and OpenAI's 2026-09-03 GPT-6 Astra release did the same to the loop's interior. Three controls that only make sense together, retiring the four assumptions every harness is built on. **Async tool calls** (`async: true`) — the model keeps generating past its own tool call, results return later on the original `call_id`, so the pending-call slot becomes a conversation-lifetime registry; plus the tell that the vendor left the scheduler in userland (`wait_for_tasks` is *your* function, `task_handle` uniqueness is a prompt-enforced invariant guarding application state). **Mid-turn steering** — `response.steer` over WebSocket, `accepted`≠applied, the `steered` incomplete reason, implicit prepending of a queued steer onto your next `response.create`, and queued input that lives only on the connection ("do not assume pending steering survived the disconnect") — de-duplication with no idempotency key. **`configuration_update`** — reasoning effort as a sticky history item rather than a request parameter, purely so the cached prefix survives (Astra: $1.00 cached vs $10.00 input vs $12.50 cache write), with four rejection rules and no read-back of the effective value. Then **misalignment monitoring** as async supervision of an async loop — auto-stop gated on exactly the conversation-continuity features this note is about, `403 misalignment_policy_violation`, and `request_paused: true` explicitly not confirming that execution stopped or that anything was reversed. Closes on the row with no vendor-side answer: nothing here can cancel, and a pending async call has no defined end of life.

- [Model Hardware Standard — The Agent-to-Instrument Layer](Model%20Hardware%20Standard%20—%20The%20Agent-to-Instrument%20Layer.md) — the fourth protocol edge (2026-08-27, research preview): after model→data (MCP) and agent→agent (A2A), model→**actuator**. A driver-and-description layer *under* MCP, not a competitor to it. Two commands (`read`/`write`) plus **states** (*plate at position 3*, *sample at 25 °C*), **procedures** (*aspirate*, *shake*), and natural-language **tags** written into the driver at setup that compile into a machine-readable device card — the same move `AGENTS.md` made for repos, applied to instruments. Three control mechanisms chosen by task shape (MCP for real-time supervision, CLI for one-shots, **code files** for long runs the devices execute without per-step model reasoning — code-execution-as-substrate arriving in the physical world, and unaffordable to skip when the loop is a 19-hour laser lock). Safety limits enforced **in the driver**, not the prompt. The pilot numbers (QuEra laser relock 96%→99.3% over 700 trials, recovery 150 s→0.9–14 s, 19 h locked vs ~1.6 unlocks/hour; CMU 3× throughput, weeks→8 h) and the four thin spots — **no rollback** for a partially-applied physical program, no published concurrency/locking primitive, programmable-interface-only, and the compute cost of long supervision windows. Read against **LAP** (arXiv, June 2026), whose primitive set is a superset on risk: reservation locks, a safety-fence handshake, and `MeasurementResult` typed with uncertainty — the item MHS most visibly lacks.

- [Tool-Call Reliability — Idempotency, Postcondition Verification, and Replay-Safe Authorization](Tool-Call%20Reliability%20—%20Idempotency%2C%20Postcondition%20Verification%2C%20and%20Replay-Safe%20Authorization.md) — two August 2026 papers on why "tool call = atomic success/fail" breaks in production: a verification-aware wrapper (postcondition checks, verify-before-retry, idempotency keys) that stops retries from duplicating side effects, and CapLease, which tracks user authorization by `(action, confirmation)` instead of by token identity to stop "semantic replay" — a lost ack causing the same $500 transfer to get approved twice under two honestly-single-use tokens (measured on 10,152 real trajectories: 39.8% repeated-call rate). Idempotency keys protect the effect; durable authorization state protects the permission — production agents that act on the world need both.
- [Computer and Browser Toolsets — Batched Actions, Ref Targeting, and the Toolset Shape](Computer%20and%20Browser%20Toolsets%20—%20Batched%20Actions%2C%20Ref%20Targeting%2C%20and%20the%20Toolset%20Shape.md) — the 2026-08-20 GA release, read for the shape change rather than the label: a single tool with an `action` enum becomes a **toolset** of narrow-schema member tools (`computer_toolset_20260801`, 17 members; `browser_toolset_20260801`, 31 members / 27 on by default), a turn carries **many actions run sequentially** instead of one (with a fail-stop contract and exact halt strings — batching turns a step sequence into a partially-applied transaction), and the browser toolset targets elements by **`ref` into an accessibility tree** (`read_page`/`find`, staleness undetectable by the API) rather than by pixel. Plus `browser_state` as a typed out-of-band channel for tab inventory the model never sees as JSON, the ~11k-token standing definition cost of enabling both, and Skills/Files becoming versioned workspace-scoped platform objects (`container.skills` + required code execution; `file_id` references, full-snapshot versioning, `"latest"` as a shared mutable pointer).
- [Agent-Native Browser Runtimes — Rebuilding the Browser for Machines, Not Humans](Agent-Native%20Browser%20Runtimes%20—%20Rebuilding%20the%20Browser%20for%20Machines%2C%20Not%20Humans.md) — Cloudflare's Kitesurf (2026-08-06): instead of reusing Chromium (computer-use pixels, or Playwright/Puppeteer CDP automation), build a browser engine with no human affordances, running in V8 isolates on Workers instead of Chromium-in-a-container. 3–7× less CPU/memory at the cost of 1.7–1.8× wall-clock, full CDP compatibility so it's a drop-in for existing tooling, and explicit non-goals (video, WebGL, TLS fingerprinting, long authenticated sessions).
- [WebMCP — The Page as Tool Server, the Session as Credential](WebMCP%20%E2%80%94%20The%20Page%20as%20Tool%20Server%2C%20the%20Session%20as%20Credential.md) — the fourth protocol layer stopped being a thing to watch: OpenAI shipped **Site tools** in the ChatGPT desktop browser (2026-08-25), the W3C Web Machine Learning CG published a Draft Community Group Report (2026-08-26), and Chrome has an origin trial running since Chrome 149. Two relocations, not one: the **tool contract** moves off a server you operate and into the live page (`document.modelContext.registerTool`, imperative and page-scoped, `toolchange` on register/unregister — progressive disclosure by navigation), and the **credential** stops being a token you provision and becomes the user's already-signed-in session — which deletes the entire OAuth/scope/rotation problem MCP's roadmap is still solving, at the price of **no attenuation** (a browser session has no read-only mode). The trust boundary inverts: tool `description`s and `execute` return values are attacker-controlled text arriving pre-formatted as an authoritative contract, and the spec's confirmation primitive is still an open question — so the only durable control is the authorization check inside your own endpoint. Plus the four structural limits (no headless, discovery-only-by-visiting, uncapped state-refactor cost, no attenuation), the `document` vs Chrome's `navigator` surface split, ChatGPT's gaps (no iframe tools, no declarative `<form>` tools, GPT-5.6 Sol/Terra only, no Enterprise/Edu), and an act-now-vs-wait table by role.
