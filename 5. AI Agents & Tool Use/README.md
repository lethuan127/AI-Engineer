- [MCP Apps Debugging — The Staged Diagnostic View and the URI Cache Trap](MCP%20Apps%20Debugging%20—%20The%20Staged%20Diagnostic%20View%20and%20the%20URI%20Cache%20Trap.md) — from a real session (2026-07-15): an MCP App that hangs on the host spinner is ~7 different bugs wearing the same UI, because every stage (resource fetch → iframe → SDK import/CSP → `connect()` handshake → tool input/result → `callServerTool`) fails silently. The debug harness: a staged diagnostic tool + view registered identically to the real app (behind a debug flag, off by default — not a production fixture), and the punchline — **hosts cache `ui://` views by URI**, so treat view URIs as immutable content addresses and bump a version suffix on every edit (`form-v2.html`); plus the 2×2 tool×view bisect.
