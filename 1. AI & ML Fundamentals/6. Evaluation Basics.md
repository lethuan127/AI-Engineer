# Evaluation Basics

If you can't measure it, you can't improve it. Eval discipline is the difference between a model that ships and one that doesn't.

## The Most Important Rule

**Pick your metric before you train.** Choosing it after biases you toward whatever you got.

## Classification Metrics

### Confusion Matrix

For a binary classifier:

```
                Predicted
              Pos      Neg
Actual Pos   TP       FN     (Recall = TP / (TP+FN))
       Neg   FP       TN     (Specificity = TN / (FP+TN))
            (Precision = TP / (TP+FP))
```

- **TP / TN** — correct predictions
- **FP** — false alarm (predicted positive, actually negative)
- **FN** — missed detection (predicted negative, actually positive)

### Core Metrics

| Metric | Formula | When to use |
|---|---|---|
| **Accuracy** | \((TP + TN) / \text{total}\) | Balanced classes only |
| **Precision** | \(TP / (TP + FP)\) | When false positives are costly (spam filter) |
| **Recall** (Sensitivity) | \(TP / (TP + FN)\) | When false negatives are costly (cancer detection) |
| **F1** | \(2 \cdot \frac{P \cdot R}{P + R}\) | Balance precision and recall |
| **ROC-AUC** | Area under ROC curve | Threshold-independent ranking quality |
| **PR-AUC** | Area under Precision-Recall curve | Better than ROC-AUC for imbalanced data |

```python
from sklearn.metrics import classification_report, confusion_matrix, roc_auc_score
print(classification_report(y_test, y_pred))
print(confusion_matrix(y_test, y_pred))
print("AUC:", roc_auc_score(y_test, y_proba))
```

### The Accuracy Trap

If 99% of emails are not spam, predicting "not spam" always gives 99% accuracy. But **recall = 0** for the actual task you care about.

**Always check class balance** and use precision / recall / F1 when imbalanced.

## Regression Metrics

| Metric | Formula | Notes |
|---|---|---|
| **MSE** | \(\frac{1}{n}\sum (y - \hat{y})^2\) | Penalizes large errors heavily |
| **RMSE** | \(\sqrt{\text{MSE}}\) | Same units as target |
| **MAE** | \(\frac{1}{n}\sum |y - \hat{y}|\) | Robust to outliers |
| **R²** | \(1 - \frac{\text{SS}_{\text{res}}}{\text{SS}_{\text{tot}}}\) | % variance explained (higher = better) |

```python
from sklearn.metrics import mean_squared_error, r2_score
print("RMSE:", mean_squared_error(y_test, y_pred, squared=False))
print("R²:", r2_score(y_test, y_pred))
```

## Ranking & Recommendation Metrics

For systems that rank items (search, recommenders):

- **Precision@k**, **Recall@k** — quality among top k results
- **MRR** (Mean Reciprocal Rank) — how high is the first relevant result?
- **NDCG** (Normalized Discounted Cumulative Gain) — graded relevance with position discount

## Generative Model Metrics

For LLMs and generative models, traditional metrics don't quite work:

- **Perplexity** — \(\exp(\text{loss})\); how "surprised" the model is. Lower is better.
- **BLEU / ROUGE** — n-gram overlap with reference (legacy translation/summarization).
- **BERTScore** — semantic similarity via embeddings.
- **LLM-as-judge** — use a strong model (GPT-4, Claude) to score outputs.
- **Human eval** — still the gold standard for open-ended tasks.
- **Task-specific eval** — e.g., does the generated SQL run? Does the code pass tests?

## Baselines

**Always compare against:**

1. **Trivial baseline**: predict the majority class / mean.
2. **Simple model**: logistic regression / linear regression.
3. **Last version**: did the new model actually improve?

If your fancy model doesn't beat #1 or #2 by a meaningful margin, something is wrong.

## Statistical Significance

A 0.5% improvement might be **noise**. For A/B testing or model comparison:

- Use **paired tests** (same examples, two models).
- Bootstrap confidence intervals are easy and assumption-free.
- Effect size matters more than p-value.

```python
from scipy import stats
t, p = stats.ttest_rel(errors_model_a, errors_model_b)  # paired t-test
```

## Common Eval Mistakes

| Mistake | Fix |
|---|---|
| Accuracy on imbalanced data | Use F1, PR-AUC |
| Tuning on the test set | Hold out test set, use validation for tuning |
| Random split on temporal data | Use **time-based split** (past → future) |
| Eval set has duplicates from training | Deduplicate before splitting |
| Ignoring per-segment performance | Slice by user type, geography, etc. |

## Slicing & Per-Segment Eval

Aggregate metrics hide failures. Always slice:

```python
from sklearn.metrics import accuracy_score
for segment in df["country"].unique():
    mask = df["country"] == segment
    print(segment, accuracy_score(y_true[mask], y_pred[mask]))
```

A model with 90% overall accuracy might be 99% on majority and 50% on minority groups — fairness and product quality both suffer.

## Takeaways

- **Pick the metric first.**
- **Accuracy is misleading** on imbalanced data.
- **Always have baselines.**
- **Slice your eval** — aggregate numbers lie.
- **Time-based splits** for temporal data.
- For LLMs, traditional metrics aren't enough — see section 6 of the main path.
