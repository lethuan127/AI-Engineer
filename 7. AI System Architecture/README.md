- [7.6. The Responses API as a Hosted Agent Loop](./7.6.%20The%20Responses%20API%20as%20a%20Hosted%20Agent%20Loop.md) — the third position on the axis `7.1`/`7.2` draw: an endpoint that looks like inference and behaves like a runtime (*"an agentic loop… within the span of one API request"*). Read through one question — **who owns the loop**. The item union replacing `messages` (a trace, not a chat log; `n` removed); why reasoning models score better here and cache better (~3% SWE-bench, 40–80% cache, and tool calling gated off Chat Completions from GPT-5.4); the **hosted-vs-client execution table** as the line that actually decides your architecture — hosted MCP means *OpenAI* originates the egress, outside every boundary [8.4](../8.%20AI%20Safety%20&%20Ethics/8.4.%20The%20Agent%20Containment%20Toolchain%20—%20Sandbox,%20Runtime,%20and%20Egress%20Proxy.md) tells you to build, and programmatic tool calling is a *hybrid* whose context saving the docs pointedly decline to quantify. Four state mechanisms and the retention asymmetry nobody reads (stored responses 30-day TTL, **conversation items none** — a compliance decision disguised as an ergonomic one), plus chaining that bills every prior token anyway. Three progressive-disclosure layers (tool search defers only the *parameter schema*; skills defer the `SKILL.md` body and run at **user** privilege; PTC defers intermediate output) versus compaction as the one mechanism that destroys information rather than deferring it — with the opposite pruning rules for server-side vs `/responses/compact`. Then the three escapes from single-response execution: `background` (the *only* real cancel), WebSocket `stream_id` lanes (~40% faster at 20+ tool calls, 60-min connections, in-memory continuation cache, and a documented cross-lane fork race), and multi-agent mode — no declarative agent list, six hosted coordination actions, and **aggregate-only usage**, which makes the ~15× token tax from [Multi-Agent Orchestration](../5.%20AI%20Agents%20&%20Tool%20Use/Multi-Agent%20Orchestration%20in%20Production%20—%20Topologies,%20Token%20Economics,%20and%20Coordination%20Failure.md) unmeasurable here. Closes on the trade stated precisely: you don't lose control, you swap *inherent* control for *granted* control — queues, error codes, and a socket that can drop — and on the observation that the happy path is specified while the failure path isn't.
- [7.7. The Agents API as a Managed Harness — Sessions, Executors, and the Split Lifecycle](./7.7.%20The%20Agents%20API%20as%20a%20Managed%20Harness%20%E2%80%94%20Sessions%2C%20Executors%2C%20and%20the%20Split%20Lifecycle.md) — OpenAI's 2026-09-10 public beta, one layer above `7.6`: that endpoint hosts a *trajectory*, this hosts an *agent*. Three structural reads. **The durable session** replaces the response as the thing you hold an ID for (a foreign key in your schema, not a config change) — and it collapses two of `7.6`'s awkward verbs into session state: input to an active session *steers* it, input to an idle one starts a turn, and `agent.session.input.cancel` finally gives the active turn a real cancel. **The executor inversion** — with `self_hosted`, you run `codex exec-server` in your own container and it dials *out* over WebSocket to a harness in OpenAI's datacenter, the reverse of every local-agent topology in `7.2`/`7.4`; egress posture improves (no inbound port, no tunnel), the decision layer leaves the building, and the executor key is readable by the agent's own code (hence: separate key, every other permission **None**). **The split lifecycle** — *"an agent session can outlive its environment"* — two state machines with no shared owner, and the seam table the docs supply as homework: a five-minute connection wait, an idle event that is explicitly *not* a safe shutdown signal, mid-turn disconnects that fail a tool inside a turn that still reports completed, no guaranteed recovery of pending input after a crash, environment-ID reuse that does not restore files, and session deletion that neither stops compute nor emits a webhook. Plus what the harness absorbed (automatic compaction, tool search appended at the tail to preserve the cache prefix, subagents with `max_concurrent_subagents` default 6 sharing one filesystem and barred from function tools), the one thing it does better than `7.6` — **per-subagent cost attribution** via `turns.usage` + `subagent_id`, best-effort and with no cache-write count — and the line that ends the conversation for regulated work: **US-only residency, no ZDR, and a self-hosted sandbox does not change that**, because the harness holds the state.
- [7.8. The Local-First Harness — On-Device Execution and Advisor Escalation](./7.8.%20The%20Local-First%20Harness%20%E2%80%94%20On-Device%20Execution%20and%20Advisor%20Escalation.md) — the mirror image of `7.7`: loop, planner, tool router, sandbox, scheduler *and* a 27B model all on the user's GPU, read off Perplexity's 2026-08-25 research post and the 2026-09-14 Windows release. The axis isn't build/buy here, it's **where the loop sits relative to the bytes it reads** — the one topology where `7.7`'s closing line about residency and the harness holding the state does not apply. Three reads. **The harness outweighs the model**: same weights across three harnesses moves the score 8.6 points; post-training the model *inside* the winning harness moves it 2.8, for 30% more tokens — and on ParseBench the same model burns 20.1k tokens/task in one harness and 829k in another, the empirical case for [11.14](../11.%20Harness%20Engineering/11.14.%20Tuning%20the%20Harness%2C%20Not%20the%20Model%20%E2%80%94%20The%20Harness%20as%20an%20Optimization%20Surface.md) and the controlled experiment [11.20](../11.%20Harness%20Engineering/11.20.%20Harness%20Benchmarking%20%E2%80%94%20Controlled%20Cross-Harness%20Evaluation.md) asks for. **Advisor escalation as an advice channel, not a delegation channel** — the frontier model returns text and never holds a tool, the PII classifier and egress preview live in the orchestrator, and the cost curve (59.6% free → 73.0% at $0.415 → 82.4% at $0.65) says you buy this for the privacy property, not the economics. Plus the numbers worth stealing: a **260K advertised window that degrades past 100K**, MCP demoted to CLI tools because tool definitions compete with the user's documents, and a sandbox that **fails closed** — the harness disables itself rather than degrade to unsandboxed execution. Caveats the unverified parts: SPACE is named with no mechanism, and the "durable task queue" appears only in product copy.
