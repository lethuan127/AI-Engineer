# 7.2. Self-Implemented Agent Harness — Components

> Companion to [7.1. Claude Platform Managed Agent](./7.1.%20Claude%20Platform%20Managed%20Agent.md). If you decide **not** to use a managed harness (Anthropic, OpenAI Assistants, etc.) and roll your own, this is the component checklist you're signing up for.

Build-tier legend:

- 🟢 **MVP** — smallest thing that works.
- 🟡 **Production** — needed before real users.
- 🔴 **Managed-grade** — needed if you're offering this as a platform to others.

---

## 1. Core Runtime (the "loop")

- 🟢 **Agent loop / orchestrator** — `model → tool calls → observations → model …` with termination conditions (max steps, max tokens, max wall-time, stop signal).
- 🟢 **Model adapter / LLM client** — provider abstraction, streaming, retries with exponential backoff, timeouts, structured-error mapping.
- 🟢 **Tool dispatcher** — parse tool-use blocks, validate inputs against JSON schema, route to handler, marshal outputs back as tool-result blocks.
- 🟡 **Parallel tool execution** — fan out independent tool calls in one turn.
- 🟡 **Loop termination guards** — runaway-loop detection, repeated-call detection, budget enforcement.

## 2. Agent & Tool Definition

- 🟢 **Agent registry** — `(name, model, system prompt, tools, MCP refs, skills)` stored as records.
- 🟢 **Tool registry** — JSON-schema'd tool defs with descriptions, namespacing.
- 🟡 **Versioning** — immutable agent versions, "latest" pointer, version pinning per session.
- 🟡 **Config validation** — schema check on agent create (catch bad tool refs, missing models).
- 🔴 **Staged rollouts** — canary / blue-green for new agent versions.

## 3. Sessions & State

- 🟢 **Session store** — `(id, agent_ref, env_ref, status, timestamps)` with a state machine: `pending → running → paused → completed/failed/cancelled`.
- 🟢 **Event log** — append-only log of every event (user msg, assistant msg, tool call, tool result, status change). Source of truth.
- 🟢 **Persistent workspace per session** — `/workspace`, `/outputs` style mounts.
- 🟡 **Pause/resume** — including filesystem snapshot/restore.
- 🟡 **Resumable conversations** — sessions survive process restarts.
- 🔴 **Session GC / TTL** — auto-cleanup of old sessions, files, snapshots.

## 4. Context Engineering

- 🟢 **Token counting** per message/turn.
- 🟢 **Context-window manager** — decide what fits each turn.
- 🟡 **Prompt caching** — provider-side cache control or client-side prefix hashing.
- 🟡 **Compaction / auto-summarization** — when nearing token cap, summarize older turns.
- 🟡 **Tool-output spill-to-disk** — outputs >N tokens written to a file, model gets preview + path. Without this, one big tool output blows the context.
- 🔴 **Semantic caching** of completions and embeddings.

## 5. Tools (3 layers)

- 🟢 **Built-in toolset** — at minimum `bash`, `read`, `write`, `edit`, `glob`, `grep`. Often add `web_fetch`, `web_search`.
- 🟢 **Custom tool support** — user-defined tools, client-executed (request out, result back).
- 🟡 **MCP client** — connect to MCP servers, marshal tool calls, handle stdio/HTTP transports.
- 🔴 **MCP tunnels** — secure ingress to private MCP servers.
- 🔴 **Tool permission model** — per-agent allowlist, per-tool scopes/secrets.

## 6. Sandbox / Execution Environment

- 🟢 **Process-level isolation** (chroot, seccomp, dropped caps) — bare minimum for `bash`.
- 🟡 **Container isolation** — Docker / OCI runtime per session.
- 🟡 **Resource limits** — CPU, memory, disk, wall-clock quotas.
- 🟡 **Network egress policy** — allowlist/denylist, DNS filtering.
- 🔴 **Strong VM isolation** — Firecracker / gVisor / Kata for multi-tenant safety.
- 🔴 **Self-hosted sandbox protocol** — work queue + worker SDK so customers can run tools in their own infra (always-on poller and/or webhook-triggered handler).

## 7. Streaming & Event Protocol

- 🟢 **Server-Sent Events (or WebSocket)** for live output.
- 🟢 **Typed event schema** — `message_delta`, `tool_use`, `tool_result`, `status`, `error`, `done`.
- 🟡 **Client → server events** — additional user inputs while loop is running (steering).
- 🟡 **Interrupt / cancel** — clean cancellation of in-flight model + tool calls.
- 🟡 **Replay / fetch full history** endpoint.
- 🔴 **Backpressure** between model stream, tool exec, and client.

## 8. Skills / Reusable Capabilities

- 🟡 **Skill format** — `SKILL.md` + supporting files, versioned, addressable by ID.
- 🟡 **Skill distribution** — download/cache into session workspace at start.
- 🔴 **Skill marketplace / sharing** across agents.

## 9. Multi-tenancy & API Surface

- 🟢 **REST API**: `agents`, `environments`, `sessions`, `events`.
- 🟢 **API keys + auth**.
- 🟡 **Org / workspace scoping** — RBAC, environment keys.
- 🟡 **Rate limits** per org, per endpoint class (create vs. read).
- 🟡 **SDK** in your primary languages (TS, Python).
- 🔴 **Webhooks** for lifecycle events (`session.run_started`, `session.completed`).

## 10. Observability

- 🟢 **Structured logs** per session, per event.
- 🟢 **Token & cost accounting** per session / agent / org.
- 🟡 **Distributed tracing** — span per model call and tool call (OpenTelemetry).
- 🟡 **Metrics** — latency, error rate, tool usage, queue depth.
- 🟡 **Audit log** — who created/modified/deleted what.
- 🔴 **Live debugger / replay UI** for support engineers.

## 11. Safety & Guardrails

- 🟢 **Hard limits** — max steps, max cost, max wall-time.
- 🟡 **Input moderation** — prompt-injection / jailbreak detection.
- 🟡 **Output moderation** — content filters, PII scrubbing.
- 🟡 **Egress controls** for tools (no random outbound).
- 🔴 **Per-tool capability scopes** — least privilege per call.

## 12. Reliability

- 🟢 **Retry policies** classified by error type (transient vs. fatal).
- 🟢 **Health checks** for model providers, MCP servers, workers.
- 🟡 **Graceful degradation** — fall back to a smaller model, disable a flaky tool.
- 🟡 **At-least-once delivery** for the work queue (idempotency keys on tool calls).
- 🔴 **Multi-region failover**.

## 13. Storage

- 🟢 **Blob storage** for outputs and uploaded files.
- 🟢 **File-reference system** — agents pass file IDs/paths, not raw contents.
- 🟡 **Encrypted at rest + in transit**, KMS-backed.
- 🔴 **Region pinning / data residency**.

## 14. Testing & Evaluation

- 🟢 **Deterministic replay** from event log with mocked model/tools.
- 🟡 **Golden-task eval harness**.
- 🟡 **Snapshot / export** sessions for bug repro.
- 🔴 **Shadow runs** — replay traffic on new agent version offline.

## 15. Compliance / Data Governance

- 🟡 **Delete APIs** for sessions and files.
- 🟡 **Configurable retention** (TTL, ZDR-style modes).
- 🔴 **HIPAA / SOC2 controls**, BAAs, audit certifications.

---

## Minimum Viable Harness (only the 🟢 items)

If you build only the green tier, you have a working but bare harness:

```text
Agent loop  +  Model client  +  Tool dispatcher
Agent/tool registry
Session store + append-only event log + workspace dir
Token counting + context-window manager
Built-in tools (bash + fs) + custom tool support
Process-level sandbox
SSE streaming with typed events
REST API + auth
Structured logs + cost accounting
Hard limits (steps / cost / time)
Retry policies + health checks
Blob storage + file refs
Deterministic replay
```

That's roughly the smallest thing that behaves like Claude Managed Agents in spirit.

Everything in 🟡 / 🔴 is what separates a hobby loop from a production-grade managed product. The honest cost of "we'll just build our own loop" usually shows up in items 4 (context engineering), 6 (sandbox), 10 (observability), and 11 (safety) — these are the ones teams under-estimate.

---

## Build vs. Buy — Decision Heuristic

Roll your own when **at least two** of the following are true:

- You need fine-grained control over the loop (custom planners, multi-agent orchestration, novel control flow).
- You have strict data-residency / ZDR / HIPAA constraints that managed offerings don't yet cover.
- Your tasks are **short and stateless** — a managed session's overhead is wasted.
- You're a platform company whose product *is* the agent harness.

Otherwise, use a managed harness and spend your engineering budget on the **agent definition** (prompt, tools, skills, evals) — that's where most of the differentiated value lives.

## Reference: How These Map to Claude Managed Agents

| Component you'd build | Provided by Managed Agents as |
|---|---|
| Agent registry + versioning | `Agent` resource (versioned) |
| Session store + state machine | `Session` resource |
| Event log + streaming | SSE `events` + persisted history |
| Sandbox + workspace | `Environment` (cloud or self-hosted) |
| Built-in tools | `agent_toolset_20260401` |
| MCP support / tunnels | First-class config + MCP tunnels |
| Prompt caching / compaction / spill | Built into the harness |
| Self-hosted execution | `self_hosted` environment + worker SDK |
| Rate limits / multi-tenancy | Org-level on the API |

Use this table to scope **which subset** you actually need to reimplement vs. which you can adopt off-the-shelf.
