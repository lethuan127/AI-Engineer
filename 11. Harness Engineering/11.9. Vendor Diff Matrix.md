# 11.9. Vendor Diff Matrix

> Companion to [11.1](./11.1.%20What%20Is%20a%20Harness.md) through [11.8](./11.8.%20Context%20Engineering%20in%20the%20Harness.md). Those notes are deliberately vendor-neutral. This one is the **versioned snapshot** of what each major coding agent actually supports, named, in May 2026. Treat it as a reference, not a recommendation — vendor surfaces churn fast, this note will need re-issuing.

Snapshot date: **2026-05-22**. Re-validate before quoting.

The four vendors with non-trivial harness surfaces are **Cursor**, **Claude Code**, **OpenAI Codex CLI**, and **GitHub Copilot CLI**. Honourable mentions (Aider, Continue, OpenCode, Cline) appear in footnotes where they have noteworthy positions.

---

## 1. Repo memory

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Primary file | `AGENTS.md` (root) | `CLAUDE.md` (root); reads `AGENTS.md` via `@`-import | `AGENTS.md` (root) | `AGENTS.md` (root) |
| Per-folder memory | Yes (nested `AGENTS.md`) | Yes (nested `CLAUDE.md` / `AGENTS.md`) | Yes | Limited |
| Legacy file | `.cursorrules` (deprecated) | — | — | — |
| `@`-import | Not natively (uses links) | Yes (`@path/to/file`) | Not yet | Not yet |
| Edit command | Manual | `/memory` opens editor | Manual | Manual |
| Cascading | Repo → folder | Repo → folder, with `~/.claude/CLAUDE.md` at user level | Repo → folder | Repo only |

Recommendation: write `AGENTS.md`; for Claude Code, add a one-line `CLAUDE.md` that contains `@AGENTS.md`.

## 2. Rules / Project instructions

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Mechanism | `.cursor/rules/*.mdc` | Memory files + skills | `AGENTS.md` + per-folder | `AGENTS.md` only |
| Activation modes | Always / Auto-Attached / Agent-Requested / Manual | Always (memory) or intent-routed (skills) | Always (memory) | Always |
| File-pattern scoping (`globs`) | Yes (first-class) | No (per-folder only) | No | No |
| Description-based routing | Yes (Agent-Requested rules) | Yes (skills) | No | No |
| Frontmatter format | YAML with `description`, `globs`, `alwaysApply` | YAML with `name`, `description` (skills) | None | None |
| Number you'd typically have | 5–30 | 2–10 skills + memory | 1 file | 1 file |

> Practical: Cursor has the most expressive rule system; Claude Code has the cleanest skill system; Codex and Copilot CLI are minimalist by design.

## 3. Skills

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Repo-scoped path | `.cursor/skills/<name>/SKILL.md` (native since Cursor 2.4, Nov 2025) | `.claude/skills/<name>/SKILL.md` | Not native | Not native |
| User-scoped path | `~/.cursor/skills/<name>/SKILL.md` | `~/.claude/skills/<name>/SKILL.md` | — | — |
| Plugin-distributed | Yes (`~/.cursor/plugins/cache/.../skills/`) | Yes (`~/.claude/plugins/cache/.../skills/`) | — | — |
| Frontmatter required | `name`, `description` | `name`, `description` | — | — |
| Routing | Agent-decided from description; or explicit via `/skill-name` with `disable-model-invocation: true` | Agent-decided from description; or explicit via `/skill-name` | — | — |
| Migration helper | Built-in `/migrate-to-skills` skill converts dynamic rules and slash-commands | Skill-creator skill | — | — |
| Anthropic Agent Skills compatible | Yes (native) | Yes (native) | No | No |

> The Anthropic Skills format is now an explicitly cross-vendor open standard (see [agentskills.io](https://agentskills.io/home), published Dec 2025). Cursor 2.4+ reads it natively. For maximum portability use the canonical `SKILL.md` layout under `.claude/skills/` or `.cursor/skills/` — both vendors will load it.

## 4. Slash commands

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Repo-scoped path | `.cursor/commands/<name>.md` | `.claude/commands/<name>.md` | — | — |
| User-scoped path | `~/.cursor/commands/` | `~/.claude/commands/` | — | — |
| Frontmatter | `description`, `argument-hint` | `description`, `argument-hint` | — | — |
| Argument placeholder | `$ARGUMENTS`, `$1`..`$N` | `$ARGUMENTS`, `$1`..`$N` | — | — |
| Invocation | `/<name> <args>` | `/<name> <args>` | — | — |
| Built-in commands | Some (`/new`, `/clear`, …) | Many (`/help`, `/compact`, `/memory`, `/cost`, …) | Few CLI flags | Few |

Codex CLI and Copilot CLI rely on prompt convention rather than a command system. If you want a `/audit-refs` shortcut, both Cursor and Claude Code support it; the CLIs require you to remember the prompt.

## 5. Subagents

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Repo-scoped definition | Limited (subagent types are mostly user-global / plugin-distributed) | Yes — `.claude/agents/<name>.md` | No | No |
| User-scoped definition | Yes (plugin-distributed) | Yes — `~/.claude/agents/` | — | — |
| Tool restriction | Yes (subagent type config) | Yes (`tools:` frontmatter) | — | — |
| Parallel dispatch | Yes (`Task` tool with multiple invocations in one message) | Yes (parallel `Task` tool) | — | — |
| Inherits parent context | No (fresh context) | No (fresh context) | — | — |
| Model override | Some plugins allow | Yes (`model:` frontmatter or `model: inherit`) | — | — |

> Claude Code currently has the most ergonomic per-repo subagent story. Cursor's subagent capability exists but is mainly authored via plugins and user-global config; per-repo subagent files are not yet first-class.

## 6. Hooks

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Config file | `.cursor/hooks.json` (top-level `version: 1`) | `.claude/settings.json` (under `hooks`) | — | — |
| Hook events (selection) | `beforeShellExecution`, `afterShellExecution`, `afterFileEdit`, `beforeReadFile`, `preToolUse`, `postToolUse`, `sessionStart`, `sessionEnd`, `subagentStart`, `stop`, `preCompact`, `workspaceOpen` | `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `Notification`, `PreCompact` | — | — |
| Payload to hook | **JSON on stdin** (`file_path`, `edits`, `tool_input`, …) | **JSON on stdin** (`tool_name`, `tool_input.file_path`, …) | — | — |
| Blocking decision | `{"permission":"deny"}` JSON / non-zero exit (with `failClosed: true`) | `{"decision":"block","reason":"…"}` JSON / non-zero exit | — | — |
| Timeout | Per-hook `timeout` (seconds) | Per-hook `timeout` (seconds) | — | — |
| Per-event filter | `matcher` field — semantics depend on event (tool type for `afterFileEdit`, command regex for `beforeShellExecution`, subagent type for `subagentStart`, …) | `matcher` field (tool name regex) | — | — |
| Cross-vendor compat | Explicitly supports loading Claude-Code-format hooks (see [Third-Party Hooks](https://cursor.com/docs/reference/third-party-hooks)) | — | — | — |

> The protocols have converged: stdio JSON in, stdio JSON out, `matcher` for filtering, `timeout` in seconds. Earlier docs (and earlier versions of this matrix) described Cursor as env-var-based — that is no longer correct. Write the *logic* once as a shared script that reads `.file_path` or `.tool_input.file_path` from stdin; wire it from both vendors' config files. This repo does exactly that.

## 7. Permissions

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Config | UI + `.cursor/settings.json` | `.claude/settings.json` (`permissions` block) | CLI flags (`--full-auto`, `--read-only`) | CLI flags |
| Tiers | Allow / Ask / Deny | Allow / Ask / Deny | Coarse (read-only or full) | Coarse |
| Glob-style patterns | Yes | Yes — `Bash(git status:*)` syntax | — | — |
| Per-MCP server scoping | Yes | Yes | — | — |
| Default for new tools | Ask (sane) | Ask | Ask | Ask |

> Cursor's UI makes it easy to discover what's been allowed; Claude Code's JSON makes it easy to check into git and review in PRs. Most teams use a mix.

## 8. MCP

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Repo-scoped config | `.cursor/mcp.json` | `.mcp.json` (also reads from `.claude/settings.json`) | `~/.codex/mcp.json` (user-scoped) | Limited |
| User-scoped config | `~/.cursor/mcp.json` | `~/.claude/mcp.json` | `~/.codex/mcp.json` | `~/.config/copilot/mcp.json` |
| Transport | stdio + HTTP | stdio + HTTP | stdio | stdio (early support) |
| `env:` block for secrets | Yes | Yes | Yes | Yes |
| `${env:VAR}` interpolation | Yes | Yes | Yes | Partial |
| Resources support | Yes | Yes | Tools only | Tools only |
| Prompts support | Limited | Yes | No | No |

> The protocol is the same; what differs is how much of MCP the client implements. Tools work everywhere; resources and prompts mostly only in Cursor and Claude Code.

## 9. Context engineering

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Auto prompt caching | Yes (vendor-side) | Yes (vendor-side) | Yes (vendor-side, model-dependent) | Yes |
| Manual compact | UI / `/clear` | `/compact`, `/clear` | `/clear` | `/clear` |
| File-system spill on large tool outputs | Yes | Yes | Yes | Limited |
| Recently-viewed files attached | Yes | Limited (current file + history) | No (CLI) | No (CLI) |
| Open terminals attached | Yes (in IDE mode) | Yes (subset) | No | No |
| Token / cost surface | UI bar | `/cost` command | CLI logging | CLI logging |
| Max context window | Model-dependent (1M+ on 4-* class) | Model-dependent | Model-dependent | Model-dependent |

> IDE-embedded agents (Cursor, Claude Code in IDE mode) silently attach more context than CLI-only agents. This is good for quality, bad for token budgets. Be intentional about what's "open".

## 11. Network egress

Often overlooked. Worth checking before you assume your MCP can phone home.

| | Cursor | Claude Code | Codex CLI | Copilot CLI |
|---|---|---|---|---|
| Network by default | Allowed (subject to perms) | Allowed | **Restricted by default** in some modes; opt-in | Allowed |
| Allowlist | Not first-class | Not first-class | Yes (workspace-net allowlist) | Not first-class |
| WebFetch tool | Allowed by default | Allowed by default | Restricted | Allowed |

> If you build an MCP that requires outbound network from the agent's process, smoke-test it in Codex CLI specifically.

| Sourcegraph Cody | Yes | Yes | — |

The convention has reached escape velocity. New projects should default to `AGENTS.md`.

## 13. Sizing this snapshot

Vendor surfaces churn on a quarterly cadence. Three things to re-check before relying on this table:

1. Each vendor's CHANGELOG for events since 2026-05-22.
2. Whether new primitives have been added (e.g., the open question of "Plans" or "Memos" becoming first-class).
3. Whether AGENTS.md import semantics have unified.

> Architectural takeaway — never assume the vendor diff matrix is static. It is closer to a npm-package compatibility chart than a language spec.
