# 11.13. Harness Engineering for Stock Investment

> Second domain-transfer note in section 11, parallel to [11.12. Harness Engineering for Private Equity & Venture Capital](./11.12.%20Harness%20Engineering%20for%20Private%20Equity%20%26%20Venture%20Capital.md). Where 11.12 covered private, illiquid, deal-by-deal investing, this note covers **public-equity investing** — a continuous-corpus, market-data-heavy, regulator-watched domain where the agent's failure modes differ in kind from coding or PE/VC.
>
> Scope assumed: a **long-only fundamental fund** (mutual fund, separately managed account, or in-house equity strategy) running an agent at **draft-and-review** autonomy — the agent proposes trades into a review queue; a PM approves; the OMS places the trade. The asides note where the picture changes for retail, RIAs, hedge funds, and quant shops.

The public-equity domain has three structural properties that change the harness's center of gravity:

1. **The corpus moves every minute** — prices, news, filings, transcripts. The deal room in 11.12 is static; the equity corpus is a firehose.
2. **The regulator is in the room** — SEC, FINRA, MAR (EU), MiFID II. Material non-public information, best-execution, suitability, market-abuse rules all bear on what the agent is allowed to read, write, and remember.
3. **The action is reversible but expensive** — a wrong refund in 11.12 costs $50; a wrong 10,000-share order at the open costs many multiples of that and shows up on the tape. Pre-trade controls are non-negotiable.

The good news: the section-11 primitives still cover it. The work is in where you put the load.

---

## 1. The portfolio as a "repository"

11.12 mapped PE/VC deals to files in a repo. The public-equity mapping is similar but with a streaming twist:

| Coding repo / PE/VC | Public equities |
|---|---|
| Files / deals | **Tickers** (positions, watchlist, universe) |
| Commits / opportunities | New filings, earnings, news, analyst notes, price moves, corporate actions |
| `README.md` / `FUND.md` | Investment policy statement (IPS); strategy guidelines; benchmark; risk budget |
| Tests | Position-size limits; sector limits; tracking error; ESG screen |
| Linter rules | Memo format; valuation methodology; comp-table conventions |
| Build pipeline | Idea → research → recommendation → PM review → trade ticket → execution → settlement |
| Production deploy | Order placement against the OMS / EMS |
| Audit | Trade log + research log + communications log, retained ≥ 5 years (SEC Rule 204-2) |

The agent's job is to advance one ticker from one stage to the next: surface a news event, draft a research note, propose a position change. **The unit of output is the trade ticket; the unit of reuse is the skill.**

## 2. Three real agent roles

As in 11.12, not one giant agent. Three narrow S2 roles ([11.1 §3](./11.1.%20What%20Is%20a%20Harness.md)) wired into the investment process:

| Role (S2) | Triggered when | Output | Tool surface |
|---|---|---|---|
| **Market monitor** | New filing (10-K, 10-Q, 8-K), news headline, price move > Nσ, earnings release | One-paragraph "is this material?" verdict + structured fields (ticker, event type, severity, owned/not-owned) | EDGAR MCP, news MCP, market-data MCP, internal positions MCP |
| **Research analyst** | A ticker advances past initial flag, or PM requests deep dive | Research memo: thesis, model, comps, risks, recommendation (BUY/HOLD/SELL/PASS) | All of the above + valuation skill, transcript MCP, broker-research MCP, portfolio-comp lookup |
| **Trade proposer** | Research recommendation triggers position change, or rebalancing event | Trade ticket draft into review queue: ticker, side, size, limit, rationale, risk impact | Positions MCP, order-management MCP (read-only + draft-only), risk-engine MCP, restricted-list MCP |

The trade-proposer role is where pre-trade controls bite hardest. It can compose the ticket; it cannot send it. The PM (or PM + compliance officer) is the gate.

> Asides — retail collapses these three into one chatty assistant; RIAs add a suitability subagent that checks every recommendation against the client's IPS; hedge funds add a *short-side analyst* and a *borrow-cost* tool; quant shops replace the research role with a *signal-research* role that reads features and writes hypotheses, never proposes trades directly.

## 3. Slot-by-slot translation

Walking the section-11 primitives, with the equity analogue and the load-bearing decision.

### 3a. Repo memory ([11.2](./11.2.%20Repo%20Memory%20%E2%80%94%20AGENTS.md%20%26%20Friends.md)) — the investment policy

Coding: `AGENTS.md`. PE/VC: `FUND.md`. Equities: **`IPS.md`** (investment policy statement), loaded into every turn.

| Section | What it contains |
|---|---|
| **Mandate** | Long-only U.S. large-cap; benchmark = S&P 500; tracking-error budget = ±300 bps |
| **Style** | GARP / quality compounders / deep value / etc. — the lens applied to every name |
| **Position sizing rules** | Initial position 1.0–2.5%; max position 5%; cash 0–5% |
| **Sector / factor limits** | ±5% vs. benchmark by GICS sector; net beta 0.85–1.15 |
| **ESG / exclusions** | Tobacco, controversial weapons, etc. |
| **Memo conventions** | Section order; required risks; comp-table format; citation style |
| **Restricted-list policy** | The agent must check the restricted list before drafting any ticket — but never reads the contents (see §4 below) |

> Lesson — `IPS.md` carries the *strategy*. It does not carry the *restricted list*. The list is data, not policy; it lives behind an MCP with an ACL.

### 3b. Rules ([11.3](./11.3.%20Rules%20and%20Project%20Instructions.md)) — conditional context

Matched by **ticker attribute** rather than file glob:

| Match key | Example rule |
|---|---|
| Sector | "When ticker is a financial, include CET1 ratio and NIM in the model summary" |
| Market cap | "When market cap < $2B, treat liquidity (ADV / position size) as a primary risk" |
| Geography | "When issuer is non-U.S., note FX hedge policy and tax-treaty implications" |
| Index membership | "When ticker is in the benchmark, recommendation must be vs. benchmark weight; for non-index names, vs. zero" |
| Earnings window | "When date is in the 48-hour pre-earnings window, do not propose trades unless explicitly overridden by PM" |

The agent reads `description` frontmatter for each rule, decides which apply to the current ticker / situation, pulls them in. Same `description`-routing primitive as Cursor's `.mdc` rules.

### 3c. Skills ([11.4](./11.4.%20Skills.md)) — packaged procedures

Equity research is more skill-heavy than PE/VC because the *procedures* are more standardized (every analyst builds a DCF the same way at a given shop). Each one is a `SKILL.md`:

| Skill | When triggered | Workflow |
|---|---|---|
| `update-thesis` | Material event on an owned name | Pull last memo; pull new filing/news; diff against stated thesis; flag confirmation / contradiction; draft thesis update |
| `screen-universe` | Periodic / on-request | Apply IPS quantitative screen across the universe; rank; emit top-20 with one-line "why" per name |
| `build-model` | New name added to coverage | Spin up the firm's three-statement template; fill from filings (gated by file IDs); flag missing inputs |
| `find-comps` | Need comparable companies | Filter by sector / size / growth; return top 8 with citations |
| `read-transcript` | Earnings call drops | Extract guidance, KPI deltas, tone shifts; cross-reference to last call |
| `draft-research-memo` | Analyst initiates / re-initiates coverage | Instantiate firm template; pull from `build-model`, `find-comps`, `update-thesis`; draft each section |
| `propose-trade` | Memo recommendation differs from current position | Compute target size from IPS rules; compute risk impact; emit draft ticket — **only** into the review queue |
| `pre-trade-checks` | Always, immediately before `propose-trade` | Restricted-list check; insider-window check; concentration check; liquidity (ADV) check; wash-sale check |

The pattern from [11.4 §7](./11.4.%20Skills.md): every analyst-facing slash command (`/screen`, `/memo`, `/propose`) delegates to the canonical skill. One source of truth; the command is the UI entry.

### 3d. Hooks and permissions ([11.5](./11.5.%20Hooks%2C%20Permissions%2C%20and%20Side%20Effects.md)) — pre-trade controls

This is where the regulator is in the room. Coding has `rm -rf`; equities has **pre-trade compliance**. The hook taxonomy is denser and the blocking tier is much larger.

| Hook point | Pattern | Example |
|---|---|---|
| **Pre-tool: any read** | Identity-scoped ACL on which tickers an analyst may research | Junior analyst can't read coverage outside her sector |
| **Pre-tool: restricted-list query** | The agent calls `is_restricted(ticker)` → boolean only; the *contents* of the list never enter the agent's context | Compliance |
| **Pre-tool: insider-window check** | If issuer is on the firm's insider-information list (M&A advisory, board seat), block ticket drafting | MNPI control |
| **Pre-tool: best-execution context** | Trade ticket must specify limit and intent (open, close, hedge); deny tickets without it | FINRA / MiFID II |
| **Pre-tool: propose-trade** | Always-block unless preceded by a successful `pre-trade-checks` skill in this session | Hard belt-and-braces |
| **Post-tool: memo emit** | Citation lint — every claim has a filing ID + page; every figure has a tier (audited > guided > model). The repo's `source-tier-prioritization` skill is exactly this pattern. | Audit |
| **Post-tool: memo emit** | Communications-style lint — no "guarantee", no "risk-free", no forward-looking statements without disclaimer | Regulator-flavored anti-pattern check |
| **Stop: session flush** | Every session's prompt, tool calls, drafts, and final state to immutable storage with actor + ticker tags | SEC Rule 204-2; MiFID II Art. 16 |

Permission tiers:

| Tier | Equity examples |
|---|---|
| `allow` | Read EDGAR; read internal positions; read market data; query restricted-list as boolean |
| `draft-and-review` | Update CRM / research log; emit research memo to analyst inbox; emit trade ticket to review queue |
| `deny` | Place an order; modify the IPS; modify the restricted list; read raw MNPI feeds; send anything externally |

> Architectural takeaway — the agent never has order-placement authority. The OMS API key is not in any environment the agent process can see. The agent's only path to a real trade is a draft that a human countersigns. This is the equity equivalent of "the agent never has the firm's chequebook" from 11.12.

### 3e. Tools and MCP ([11.7](./11.7.%20Tools%20and%20MCP.md)) — the market-data plumbing

The MCP loadout is the densest of any harness in this section because public-equity data is fragmented across many vendors. A realistic configuration:

| MCP server | Surface | Tier |
|---|---|---|
| **EDGAR / SEDAR MCP** | Filings (10-K, 10-Q, 8-K, S-1, …); full-text search; section extraction | Allow (public) |
| **Market-data MCP** | Prices, volume, ADV, corporate actions, splits, dividends (Polygon / Refinitiv / Bloomberg via internal proxy) | Allow |
| **News MCP** | Headline + body; entity-tagged; configurable lookback (Reuters / Bloomberg / Benzinga) | Allow |
| **Transcript MCP** | Earnings calls, conference appearances (AlphaSense / Sentieo / internal) | Allow |
| **Fundamentals MCP** | Standardized financial statements, KPIs, ratios (FactSet / Refinitiv / internal warehouse) | Allow |
| **Comps / valuation MCP** | Multiples, transaction comps, screens | Allow |
| **Positions MCP** | Internal holdings, weights, P&L (internal warehouse) | Allow (per-analyst ACL) |
| **Risk MCP** | Pre-trade what-if: marginal contribution to risk, tracking error, factor exposures | Allow (read-only) |
| **OMS MCP (draft-only)** | Write trade tickets into a review queue; *cannot* place orders | Draft-and-review |
| **Restricted-list MCP** | Boolean `is_restricted(ticker)`; never returns the list itself | Allow (boolean-only) |
| **Compliance MCP** | Insider-window check; wash-sale check; cross-trade check | Allow (read-only) |

> Rule of thumb from [11.7 §6](./11.7.%20Tools%20and%20MCP.md): every MCP earns its description-tax tokens. Eleven MCPs is at the high end of viable; consolidate where you can (a single "fundamentals" MCP that fronts multiple vendors is better than four separate ones, because the agent doesn't have to choose).

### 3f. Subagents ([11.6](./11.6.%20Slash%20Commands%20and%20Subagents.md)) — narrow children

Five recurring patterns:

| Subagent | Charter | Tool restriction |
|---|---|---|
| `filing-reader` | Read a long 10-K, return structured extracts (segments, risks, MD&A highlights) | Read-only; high context budget |
| `comp-finder` | Build the comp table | Read-only; isolate from parent context |
| `risk-flagger` | Annotate the draft memo with risk flags | Read-only; no write tools |
| `compliance-reviewer` | Independent verdict on draft memo + ticket; reads the IPS, restricted-list boolean, insider-window | Read-only; cannot see the parent's reasoning before forming opinion |
| `model-builder` | Fill the three-statement template from filings | Write (scoped to model file); long-running |

The repo's `reference-validator` is the coding analogue of `compliance-reviewer` — narrow, read-only, returns a verdict.

### 3g. Context engineering ([11.8](./11.8.%20Context%20Engineering%20in%20the%20Harness.md)) — the streaming-corpus problem

PE/VC had the "deal room is too big" problem. Equities has the **stream is too fast** problem.

Three patterns:

1. **Time-windowed attachment.** The harness pulls only the last N hours of news + filings into context by default; older material is reachable via tool, not preloaded. Mirror of the recently-viewed-files attachment in coding harnesses.
2. **Per-ticker scratchpad.** A `tickers/<TICKER>/notes.md` lives in the firm's research store. The agent appends findings; the next session loads it. Section-11.8 filesystem-as-memory pattern.
3. **Aggressive compaction across sessions.** Research on a single name spans weeks. Compact at memo-emit boundaries: "Here is the thesis as of 2026-05-22; underlying transcripts and models are at `<store>/tickers/AAPL/2026-Q2/`."

A fourth pattern unique to equities: **never put live prices in repo memory.** They go stale within minutes and would force a cache invalidation on every turn. Prices flow only through tool calls.

### 3h. Slash commands ([11.6](./11.6.%20Slash%20Commands%20and%20Subagents.md))

Analyst- and PM-facing buttons; each delegates to a skill:

| Command | Effect |
|---|---|
| `/monitor` | Run the market-monitor agent across the portfolio for the last N hours |
| `/screen <criteria>` | Run `screen-universe` |
| `/memo <ticker>` | Run `draft-research-memo`; open in analyst's editor |
| `/comps <ticker>` | Run `find-comps`; emit markdown table |
| `/propose <ticker> <action>` | Run `pre-trade-checks` then `propose-trade`; ticket lands in review queue |
| `/review-queue` | List pending tickets for PM sign-off |

## 4. Two new primitives — MNPI walls and pre-trade controls

11.12 introduced **identity propagation** as the enterprise primitive coding harnesses don't need. Equities adds two more.

### 4a. The information barrier (Chinese wall)

Some staff have access to material non-public information (an M&A advisory mandate, a board seat, a private financing). When they do, the public-side investment agent must not see anything they have seen.

```text
┌─ public-side analyst (Alice) ──────┐    ┌─ private-side advisor (Bob) ─────┐
│  agent reads: filings, news,       │    │  agent reads: M&A files, NDA     │
│      transcripts, comps            │    │      docs, deal-room             │
│  agent cannot read: restricted     │    │  agent cannot publish: anything  │
│      list contents, MNPI feeds     │    │      to the public-side store    │
└─────────────┬──────────────────────┘    └───────────────┬──────────────────┘
              │                                           │
              │     ┌─────────────────────────────┐       │
              └────▶│  Restricted-list MCP        │◀──────┘
                    │  (boolean queries only;     │
                    │   contents never returned   │
                    │   to either agent context)  │
                    └─────────────────────────────┘
```

Implementation rules:

1. **Two separate `IPS.md` / repo-memory files.** Public-side and private-side never share a session.
2. **Restricted-list MCP returns booleans.** The contents are never tokens in any agent context. This is the only way to honestly enforce the wall — a model that has seen the list once will leak it.
3. **The audit log carries which side the session was on.** Compliance can reconstruct the wall after the fact.

### 4b. Hard pre-trade limit checks

Pre-trade compliance is a **gate, not a hook**. The distinction matters:

- A *hook* is advisory or blocking-with-override.
- A *gate* is mathematically derived from the IPS + position state + market state. It cannot be overridden by the model and only narrowly by the PM (with a reason and a logged override).

```text
            ┌────── propose_trade(ticker=X, side=BUY, qty=10000, limit=...) ──────┐
            │                                                                    │
            ▼                                                                    │
   ┌────────────────────┐                                                        │
   │ restricted-list?   │── true ──▶ DENY (no override; compliance-only)         │
   └────────┬───────────┘                                                        │
            │ false                                                              │
            ▼                                                                    │
   ┌────────────────────┐                                                        │
   │ insider-window?    │── true ──▶ DENY (override: written compliance memo)    │
   └────────┬───────────┘                                                        │
            │ false                                                              │
            ▼                                                                    │
   ┌────────────────────┐                                                        │
   │ position size      │── > 5% ──▶ DENY (override: PM, sized to limit)         │
   │ post-trade?        │                                                        │
   └────────┬───────────┘                                                        │
            │ ≤ 5%                                                               │
            ▼                                                                    │
   ┌────────────────────┐                                                        │
   │ liquidity check    │── qty > X% ADV ──▶ DENY (override: PM, smaller size)   │
   └────────┬───────────┘                                                        │
            │ ok                                                                 │
            ▼                                                                    │
   ┌────────────────────┐                                                        │
   │ sector / factor    │── breach ──▶ DENY (override: PM, rebalance plan)       │
   │ limit              │                                                        │
   └────────┬───────────┘                                                        │
            │ ok                                                                 │
            ▼                                                                    │
       Draft ticket lands in review queue ──── PM signs ───▶ OMS                 │
                                                                                 │
            (every override is logged with actor + reason)  ◀────────────────────┘
```

This is the equity-specific analogue of the deny / ask / allow tiers from 11.5 §4 — but with multiple denials in a deliberate order and a structured override path. **Order matters**: cheap checks first (boolean restricted-list), expensive checks last (factor model), so most rejected trades are killed early without burning compute.

## 5. Operational concerns vs. [11.11](./11.11.%20Operational%20Concerns.md)

The PE/VC table from 11.12 §5 still applies; equities add four equity-specific concerns:

| Concern | Note |
|---|---|
| **Eval is harder.** | "Did the agent recommend what the human did?" — fine for PE/VC where the outcome is one decision. For equities you must also score "and was the recommendation right?" against subsequent returns. Run eval over 6-month and 12-month forward windows; expect noise. |
| **Backtesting the harness, not just the signal.** | When you change the `IPS.md` or a skill, you change the agent's recommendations. Replay historical events through the harness and diff the recommendation log. Same shape as drift detection in 11.11. |
| **Best-execution audit.** | MiFID II / FINRA expect a recoverable explanation for *why* a trade was the right size, route, and timing. The agent's reasoning trace becomes part of best-ex documentation. Design the audit log to be best-ex-queryable from day one. |
| **Market-abuse surveillance.** | The same audit log that proves best-ex is the one that proves the absence of front-running, painting-the-tape, or insider trading. Build it as a primary feature, not an afterthought. |

## 6. When *not* to build a stock-investment harness

The sniff test from [11.1 §4](./11.1.%20What%20Is%20a%20Harness.md), specialized:

| Situation | Verdict |
|---|---|
| "Summarize this 10-K" | One-shot API call. No harness. |
| "Score 500 names on a fixed quant signal nightly" | Workflow, not an agent. Scheduled job + LLM step. |
| "Re-balance the portfolio to target weights once a quarter" | Workflow. Deterministic. The agent has no decision to make. |
| "Read all earnings releases tonight, surface anything material on owned names" | **Agent harness.** Open-ended what-counts-as-material, model picks which to dig deeper into. |
| "Continuously monitor the portfolio + universe, propose changes, route through compliance" | **Agent harness.** This is what this note covers. |
| "Run a fully autonomous algo strategy" | **Not an agent harness.** Algo-trading systems are deterministic execution engines with quant models, not LLM-driven loops. Different discipline (low-latency systems engineering, exchange certifications, kill-switches), out of scope for section 11. |

The last row matters. **An LLM in the order-placement path is almost never the right design.** Even firms that use LLMs heavily in research keep them entirely out of execution. If you find yourself drafting an "LLM places trades" architecture, stop and re-read this section's §4b.

## 7. Adoption arc — 90 days

Same shape as 11.12; the order is more strict because the consequences of a misordered rollout are larger:

| Phase | Weeks | Ships |
|---|---|---|
| **0 — One skill, no agent** | 1–2 | `read-transcript` or `find-comps` invoked manually. Pure win. |
| **1 — IPS as memory** | 3 | `IPS.md` checked into research repo; loaded by every analyst session. |
| **2 — Read-only MCPs** | 4–6 | EDGAR, market-data, fundamentals MCPs. Agent can now research but not propose. |
| **3 — Identity + audit + Chinese wall** | 7–9 | Identity propagation; immutable session log; restricted-list MCP (boolean only); two separate session profiles for public/private side. Compliance signs off. |
| **4 — Pre-trade controls** | 10–11 | The §4b gate fully implemented. Draft-only OMS MCP. Override workflow with logged reasons. |
| **5 — First role goes live** | 12 | `market-monitor` to one PM. Eval against a historical week of events. |
| **6 — Research analyst** | 13–14 | `research-analyst` role; eval on coverage names. |
| **7 — Trade proposer (still draft-only)** | 15+ | Only after weeks of monitor + research operation. Quarterly governance cycle established. |

The order: **memory → read-only MCPs → identity & audit → pre-trade gate → roles → eval**. Skipping the pre-trade gate before the trade-proposer role goes live is the failure mode that ends careers, not just projects.

## 8. One-sentence summary

> An equity-investment harness is the same primitives as section 11 — repo memory, rules, skills, hooks, MCP, subagents — bolted to a streaming corpus (filings, news, prices), defending the firm against the order-placement boundary with **information barriers and an executable pre-trade gate**, and producing a single output (a trade ticket) that a human countersigns before it ever leaves the building.

The discipline is unchanged. The Chinese wall, the boolean restricted-list MCP, and the pre-trade gate are the equity-specific primitives. Everything else is section 11 with the labels swapped.
