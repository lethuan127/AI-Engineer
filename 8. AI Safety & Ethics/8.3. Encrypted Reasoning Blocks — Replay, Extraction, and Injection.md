# 8.3. Encrypted Reasoning Blocks — Replay, Extraction, and Injection

> Companion to [8.1. Agent Containment & Control](./8.1.%20Agent%20Containment%20%26%20Control%20—%20Capping%20the%20Blast%20Radius.md). That note caps what an agent can *do*; this note is about a trust boundary in what an agent *carries* — the opaque reasoning state every stateless multi-turn loop replays through the client.

In August 2026, researchers from ELLIS Tübingen and MPI-IS published *Stealing Reasoning Traces from Proprietary LLM APIs* (arXiv:2608.09867), turning a replay curiosity into a scaled extraction attack against Anthropic, OpenAI, and Google. The encrypted "thinking" blocks these providers hand back to API clients turned out to be portable across sessions, users, and models within a provider — and a weaker, less-safeguarded model from the same family could be prompted to decode a stronger model's hidden chain-of-thought in plaintext. Decoding 315,320 reasoning blocks scraped from public agent logs recovered 367 PII artifacts and 182 credentials. If you build agents that manage conversation history client-side — which is most of them — this changes how you must treat these blobs.

> Why it matters: every stateless agent loop replays reasoning blocks by design. The vendors told you the blob is opaque and safe to pass around. It was neither: it was decodable by the vendor's own cheaper model, replayable from any account, and a carrier for invisible prompt injection. The blob is model state, and model state is sensitive data.

---

## 1. The primitive: client-carried reasoning state

Reasoning models produce a hidden chain-of-thought that providers deliberately withhold — to protect IP from distillation and to avoid exposing unsafe intermediate content. But API conversations are not always server-side sessions. In stateless, zero-retention, tool-loop, or client-managed-history modes, the *client* carries the transcript forward. To let reasoning survive across turns without exposing it, each provider ships the raw CoT back to the client as an encrypted blob the client must replay verbatim on the next request:

| Provider | Mechanism | Client contract |
|---|---|---|
| OpenAI | Encrypted reasoning items (Responses API) | Replay items when manually managing stateless history |
| Anthropic | Thinking blocks carrying an encrypted `signature` | Return blocks unmodified in subsequent turns |
| Google | Encrypted thought signatures (Gemini API) | Pass signatures back; backend manages cross-model compatibility |

The design is sound in intent: the server keeps no per-conversation state, the client keeps no plaintext CoT, and tampering with any byte produces an API error. The failure is in what the authenticated encryption does *not* bind.
